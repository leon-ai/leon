# Working on the web app

Root instructions apply; these are web-specific additions.

## Reuse and architecture

- Include utilities, hooks, shared components, styles, packages and relevant tests in reuse searches. Prefer small backward-compatible options/variants preserving defaults; add focused abstractions/dependencies only when existing code cannot reasonably fit.
- Inspect installed TanStack packages before routing, server-state, long-list, form, shortcut, debounce/throttle or interaction-heavy work. Prefer Router for routing, Query for server state/request lifecycle, Virtual for long/dynamic lists. Reuse suitable installed facilities; propose missing TanStack packages with avoided complexity and maintainability/performance benefits before installing, never by default.
- Distinguish filesystem paths, URLs and bundler module IDs: use Node path utilities, URL utilities and Vite normalization respectively where needed. Never split filesystem paths on hardcoded separators; verify build-tool changes on Windows and POSIX.
- Use shared request/toast facilities for explicit owner actions: confirm management mutations after server acceptance, report actionable failures once. Preserve profile isolation; never duplicate cache-owned errors or toast background fetches, streaming updates or optimistic success.

## Design intent

- Make Leon cozy, warm, quietly creative and unhurried: a human-centered space for craft without urgency, hype, FOMO or production pressure. Support the owner's pace with clear, friendly language, soft forms, calm hierarchy and restrained, purposeful motion; avoid decorative noise.
- Keep typing, navigation, loading and feedback responsive, without artificial waits or blocking motion. Express warmth through existing palette/interactions, not new colors.

## Design tokens and shared styles

- Use sentence case for authored titles, headings, labels, tooltips and toasts; preserve proper names, acronyms, filenames and user/model-authored content.
- Check `src/styles/_includes/themes.sass`, `variables.sass` and existing components first. Reuse suitable semantic tokens/shared components for colors, gradients, spacing, typography, radii, shadows and motion. Choose by purpose, not matching values: overlay/pressed-shadow colors are not unrelated surfaces/floating shadows. No local copies, one-off colors, derived palettes or redundant aliases. Explain and agree on missing tokens before defining them centrally for both themes.
- Keep necessary geometry local, not one global token per measurement. `currentColor`, transparency and black/white coverage masks are not new palette colors.
- Keep foundations/behavior consistent while allowing deliberate density, hierarchy and emphasis through small, explicit, reusable component/pattern-owned variants/modifiers. Reuse tokens and preserve interaction states/accessibility; do not alter global defaults for local layouts or scatter equivalent control overrides.
- Size label typography, icons, geometry and hit areas independently; align controls, balance visual weight and verify rendered optical corrections. Main icons, brands and secondary indicators need not match labels. Icon-only buttons must be circular. Feed action toolbars share message-metadata hit areas/glyph sizes through the shared button.
- Render local SVGs through the shared icon component. Preserve original artwork; round only explicitly approved icons without changing silhouette, details, orientation or meaning. Keep canvas/optical weight consistent. Resolve dynamic names via an allowlisted local registry with compatibility aliases and category/generic fallbacks; never inject untrusted SVG or fetch/generate unknown icons at runtime. Preserve accurate brands, provenance and licenses; modifications do not remove upstream rights or authorize an independent published set.
- Use outline action icons and filled state/status variants (e.g. pinned sessions, fast service tier). Preserve explicit line/fill variants through the shared renderer; fill-based outline geometry is not a filled icon.
- Express icon actions through suitable SVG parts, animating once on hover/keyboard focus with reduced-motion support. Keep common icons readily available, uncommon assets locally cached; never load the whole catalog.
- Stateful icon controls use the shared morph renderer with explicitly authored compatible path pairs respecting approved original artwork and filled/outline styles. Animate state changes, never initial renders/remounts; retain final shapes/meaning and reverse interruptions from current geometry. Confirm async success before displaying it. Use finite native animations, skip motion when reduced and clean up on unmount; no per-frame React work or arbitrary SVG runtime normalization.
- Meet WCAG 2.2 AA target sizing independently of glyph size; consider enhanced 44px touch targets where feasible and prevent overlap. Check narrow layouts, long labels, both themes and keyboard focus without inconsistently shrinking controls.
- Keep answer-selection policy in runtime guidance. Aurora uses shared components/supported tokens, validated design constraints and authored CSS below shared controls. Preserve generated-code isolation, CSP/ancestor-navigation restrictions, bounded bridge, local assets and explicit host-side submission confirmation. Never relax isolation for CDNs or equate source validation with browser rendering; verify readable, responsive feed-width compositions in both themes.
- Use trusted server-driven connection widgets for account setup, not generated UI/ordinary Aurora forms. Keep credentials out of chat, drafts, browser persistence, query data and mutation variables; clear fields after every attempt. Preserve server-owned connection recommendations/setup lifecycle; cancellation or transport errors must not silently switch authentication methods.
- Catalogs share contact, maintenance-badge, branding and documentation components. Separate creators from current maintainers; trust server-validated provenance, never client-declared official labels. Load optional README/screenshots/changelogs on demand; render only bounded authenticated package-local images.
- Catalog/connection-card shared package icons resolve declared local `logo.svg`, then declared icon, then generic fallback. Preserve logo colors and transparent symbols without background tiles. Activities may use logos only with explicit `logo_mask`: `alpha` for transparent silhouettes, `inverse-luminance` to remove white fills from black-and-white artwork. Use existing text/activity colors for masks; fall back to `icon_name` if undeclared, unavailable or unsupported. Never infer modes from brands, parse/inject SVGs or recolor catalog/connection logos. Keep action/status icons semantic. Store static glyphs in `public/img/icons/`; inline paths serve authored part animations/morphs. Load assets independently of morph bundles.

## Performance and lifecycle

- Treat interaction speed, startup latency, CPU/GPU activity, bounded memory and idle/battery efficiency as requirements. Reuse facilities before custom effects/interaction infrastructure; profile suspected bottlenecks before speculative optimization.
- Keep virtualizer key callbacks and other cache-sensitive options stable while their underlying collection is unchanged. Inspect the installed implementation's cache dependencies; virtualization alone does not prevent full-collection work on scroll. Apply this to nested tool/output lists as well as feeds and sidebars.
- Keep unchanged row content outside scroll-range renders. Use appropriate memoization with stable callbacks and primitive or memoized props; fresh style objects and inline handlers defeat shallow comparisons. Preserve live updates, disclosures, keyboard focus and native selections. Render settled historical content without mounting unnecessary animation hooks/listeners.
- Own/clean up listeners, observers, timers, animation frames, browser animations and async operations. Cancel obsolete work, prevent stale completions and release resources on unmount. Closing must release content/effects with reduced motion, interruptions, zero durations and rapid toggles; never rely solely on animation/transition events.
- Prefer suitable CSS/browser-managed animations; keep per-frame work outside React state. CSS motion and compositor layers still consume resources: measure continuous decorations at idle, including blur/filter effects, and avoid blanket layer promotion. Run loops only while useful; pause unnecessary work when hidden, off-screen, inactive or under reduced motion. Bound canvas resolution, particles and drawing frequency.
- Preserve smooth, continuous motion for visible working sessions, composer particles and focused carets. Keep the resting composer glow static, with finite interaction feedback. Reuse shared animation visibility subscriptions/observation and existing renderer pauses instead of adding document listeners or frame loops to every row. Do not introduce stepped sweeps, repetition gaps or idle cutoffs as invisible optimizations; assess visual fidelity alongside resource use and distinguish rendering efficiencies from savings caused by changing the appearance.
- Profile moving SVG gradients and text backgrounds for repeated layout/paint. Prefer bounded cached visual layers and composited transforms when comparisons confirm a benefit while preserving the effect. Keep real labels selectable and accessible, visual copies inert and absent from DOM text extraction, snapshots current with text/icon/geometry changes, and SVG fragment IDs isolated. Release visual layers when motion stops. Batch canvas paths sharing paint state and verify dash seams, fading and pixel coverage before claiming equivalent output.
- Keep typing/scroll/pointer/resize hot paths small: batch layout reads before writes or synchronous React commits, coalesce measurements and avoid broad listeners triggering unrelated layout/renders. Observe relevant geometry changes instead of reading layout after every render; avoid repeatedly measuring every visible row.
- Scrolling moves rows beneath a stationary pointer. Hover-driven title motion, tooltips, previews and prefetch must not repeatedly start expensive work for passing rows. Respect scroll state and actual pointer intent, cancel obsolete work and preserve keyboard access; defer measurement itself, not merely the resulting animation.
- Virtualize long/dynamic collections; bound DOM including large text/structured row payloads. Scope caches/registries with eviction; hiding entries does not bound memory.
- Keep optional rendering engines and heavy assets outside startup; load or prepare them on demonstrated demand through existing facilities. Bound background fetching, polling and subscriptions, and release unused work rather than relying only on browser throttling.
- Verify performance-sensitive changes in production builds with realistic short/long answers, nested tool groups and large session lists. Compare before/after traces under matching workloads, visibility, viewport and CPU throttling; inspect frame times, scripting, layout/paint, allocations and retained resources. Exercise repeated navigation, open/close, typing, scrolling and reduced motion. Keep regression checks focused on observable contracts; do not make noisy timing thresholds or private-wiring assertions the sole protection.
- Compare resource usage over sampling intervals, state units and CPU normalization, and distinguish idle, background, scrolling and streaming states. Separate renderer, browser/GPU, backend and helper costs. Shared browser/GPU process totals cannot be attributed to one tab; CPU usage of a GPU process is not GPU utilization. Distinguish RSS/shared mappings, retained caches and normal heap fluctuation from reproducible leaks. Report measured gains and attribution/verification limits without claiming unmeasured improvements.
- Use `pnpm exec playwright test --config test/web-app/performance.playwright.config.ts` for serial, headed production resource samples at 1x/2x pixel density with isolated long-history/large-sidebar fixtures. It attaches CPU, rendering counters, heap and GPU configuration to each result under `test/web-app/benchmarks/results/`; compare matching workloads and hardware with other test browsers closed. Keep noisy CPU limits out of correctness tests; use `e2e/motion.spec.ts` and scrolling checks for observable regression coverage.

## Verification

- Keep Aurora previews and relevant states synchronized with component/widget/feed changes; reuse real components, not preview-only copies.
- Use Playwright browser E2E for web behavior, not unit/component tests. Keep independent tests fully parallel with bounded workers, isolated contexts/data, user-facing locators and auto-waiting assertions. Cover normal/reduced motion; retain useful failure traces. Never use owner profiles or paid live LLMs; distinguish deterministic API-fixture UI from full-stack coverage.
